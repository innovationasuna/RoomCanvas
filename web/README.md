# 网页编辑器

RoomCanvas 的网页部分：房间选择页（`index.html`）列出房间，点进布置编辑器（`editor/`）。

编辑器在浏览器里按真实尺寸布置重建出的房间：单击家具查看尺寸和位置，拖动或用摇杆、转盘、升降拉杆调整，确认后放置；家具可以收进家具库再放回；逐三角面检测碰撞和支撑面，可撤销重做，布局保存在当前浏览器里，也能导入导出 JSON。纯前端，使用 Three.js r180（`vendor/`，与 npm `three@0.180.0` 逐字节一致），没有构建步骤。

## 启动

本机需要 Git、Python 3 和 SSH 客户端，网页无需安装 Python 包或执行前端构建。服务器先按 [物体重建部署](../docs/OBJECT_RECONSTRUCTION.md#部署) 安装并启动 API；要在网页上重建房间，再按 [从网页重建房间](../docs/ROOM_RECONSTRUCTION.md#从网页重建房间) 启动房间重建服务。

**本机**，任意目录先执行 `ssh '<SSH 主机>'` 验证登录，登录后用 `exit` 返回本机。主机可用 `~/.ssh/config` 中的别名或 `user@host`。然后从准备存放源码的目录开始（已有仓库则直接进入 `RoomCanvas/`，省略克隆）：

```bash
git clone https://github.com/innovationasuna/RoomCanvas.git
cd RoomCanvas
python3 web/scripts/serve.py --ssh '<SSH 主机>'
```

打开 <http://127.0.0.1:7880/web/>，选择房间。`serve.py` 用一条 SSH 连接建立两个隧道：本机 `127.0.0.1:7865` 到 SSH 主机一侧的物体重建服务 `127.0.0.1:7862`，本机 `127.0.0.1:7866` 到房间重建服务 `127.0.0.1:7866`。按 `Ctrl-C` 停止网页时隧道一起关闭。房间重建服务没有启动时，原有房间和添加家具照常使用，只是“重建房间”提示服务未连接。后续从本机 `RoomCanvas/` 运行同一启动命令即可；更新代码时先停止网页，再执行 `git pull --ff-only`。

**本机**，在 `RoomCanvas/` 根目录，服务不是监听 SSH 主机的回环地址时，用以下命令替代启动命令：

```bash
python3 web/scripts/serve.py --ssh '<SSH 主机>' --remote '<监听地址>:7862'
```

`<监听地址>` 要填从 SSH 主机能连接的服务地址；服务器的 `--host` 必须绑定可由这一侧访问的接口。容器中监听 `0.0.0.0` 时，用宿主机映射地址或可达的容器 IP 作 `--remote`，不填 `0.0.0.0`。地址对应关系见 [启动与检查](../docs/OBJECT_RECONSTRUCTION.md#启动与检查)。房间重建服务的地址不同时加 `--room-remote '<地址>:<端口>'`。本机隧道端口需更换时，加 `--viewforge http://127.0.0.1:<端口>` 或 `--room-backend http://127.0.0.1:<端口>`。

**本机**，在 `RoomCanvas/` 根目录，只用编辑器时执行：

```bash
python3 web/scripts/serve.py
```

无需服务器也能打开示例房间、调整布局；[添加与导入家具](#添加与导入家具) 需要物体服务在线，[重建房间](#重建房间) 需要房间重建服务在线。如果已有外部隧道，同样省略 `--ssh`，并确保隧道在 `127.0.0.1:7865` / `7866`，或用 `--viewforge` / `--room-backend` 指向它。

## 界面

编辑器是深灰框架、黄铜色选中反馈和明亮的三维画布。左侧窄栏上方是家具库、撤销、重做，下方是手势、环境和设置；这些面板一次只展开一个，开合不改变画布大小和镜头。

- **选择和调整分开**：单击家具只显示详情（宽、深、高，相对初始位置的 X / Z / 高度偏移和旋转角度），不改变位置。拖动已选家具，或拖动详情面板里的移动摇杆、旋转转盘、升降拉杆，进入调整预览；拉杆离中心越远速度越快。确认或取消后结束，确认后可撤销重做。壁挂物用摇杆沿墙移动，可以换墙。
- **镜头**：中键拖动旋转，右键拖动平移，滚轮缩放；左键只选择和调整家具，拖动空白处不转镜头。右下角“整体” / “俯视”切换视角。
- **家具库**：按“房间中 / 已收纳”筛选，可搜索，显示实物缩略图和尺寸。第一张卡片是“添加家具”，下方“从已生成的模型添加”导入已有的重建结果。
- **布置 / 体验**：顶部切换。“体验”里可以点击开合部件，或“走进房间”漫游。还有待确认的调整时，会先提示确认或取消。
- **房间菜单**：点击房间名，可继续上次布置、导入 / 导出布局、收起全部家具或恢复原始布置。每次打开先显示原始布置，不自动覆盖或恢复上次的存档；批量操作也能撤销。
- **设置**：简洁 / 完整工具、操作提示开关、重新查看上手引导，保存在当前浏览器。简洁模式选中家具后收起家具库；完整模式在宽屏同时显示家具库与详情，并在“环境”里提供顶灯角度、近侧墙、调色等更多选项。
- **地面网格**：主格 1 米、细格 25 厘米，远处和接近平视时淡出，只作比例参照，不参与选择、碰撞和支撑；在“环境”中开关，漫游时隐藏。
- **上手引导**：随选择、调整提示下一步，可收起；保存状态会说明是否已存到当前浏览器。

界面过渡在 220 毫秒以内，只作用于界面，系统开启“减少动态效果”时停用。Manrope 字体随 `assets/fonts/` 离线提供（SIL Open Font License，同目录 `manrope-OFL.txt`），中文用系统字体。

## 房间文件

一个房间就是一个目录，里面两个文件：

- `Room.glb`：重建出的模型；
- `room_objects.json`：物品清单，用 `scripts/room_objects.py` 从重建结果的 `room_layout.json` 生成。

清单记录每件东西是房间结构、门窗、固定设施（插座、灯、窗帘、暖气片等，留在原处），还是可移动的家具；哪些东西一起移动（桌子连同桌上的东西、书架连同书）、挂在哪面墙上、哪些表面能放东西。房间重建时用 TRELLIS 重新生成的小物件（`room_layout.json` 中标有 `rebuilt`）单独成组，可以单独移动；放在家具上时随家具一起移动。家具名默认按类别自动生成（“柜子 1”）；在 `groups` 里给某组加 `"name": "钢琴"` 即可使用自定义名字，重新生成清单时会保留。

能开合的部件（柜门、房门、窗扇、升降桌）记在清单的 `joints` 里。`room_objects.py` 读取重建结果中每件物品的 `sim/<物品>.urdf`（默认在 `room_preview` 旁边的 `../room/Objects`，其他位置用 `--joints <目录>` 指定），只保留在 `Room.glb` 中能对应上的部件：部件是单独的节点，原点正好在关节上，自身不带旋转和缩放。对应不上的会打印原因并跳过。

编辑器打开房间时还会自动：从椅子网格中找出座面；把墙角的短墙连到两侧长墙上，使它们一起变淡；把没有记录墙面的窗帘归到它前方的墙。

### 房间选择页

房间选择页列出 `rooms.json` 里的房间（`id`、名字、目录、一句介绍），以及房间重建服务已完成的房间（服务在线时由 `serve.py` 合并进列表，不改写 `rooms.json`）。卡片上的家具数和模型大小直接从房间文件读取，缩略图是房间目录中的 `thumbnail.jpg`，由 `scripts/thumbnail.py` 从编辑器整体视角截图生成（需要 Playwright 和 Pillow）。手动添加房间只需在 `rooms.json` 加一行并生成缩略图。

打开方式：列表里的房间是 `editor/?room=<id>`；任意房间目录用 `editor/?scene=<相对 editor/ 的路径>`，例如 `editor/?scene=../../samples/room3`。要把编辑器发布到仓库外某个房间目录旁边，运行 `python3 web/scripts/publish.py --scene-dir <房间目录>`。

房间选择页与编辑器共用 `theme.css` 中的配色（`--rc-*` 变量）和 Manrope 字体；选择页布局在 `home.css` / `home.mjs`，编辑器布局在 `editor/form-workspace.css`。

## 重建房间

房间选择页的 **重建房间**（也可直接打开 `web/#reconstruct`）上传一个房间的完整扫描 ZIP（最大 2 GB），提交后显示实际的流水线阶段，失败可以重试；关闭页面不影响服务器上的任务，完成的房间自动加入列表。`serve.py` 只把 `/room-reconstruction/` 下的健康检查、任务、目录和已发布文件转给房间重建服务，写请求只接受本页面发出的，大文件分块转发。扫描格式、服务启动和接口见 [从网页重建房间](../docs/ROOM_RECONSTRUCTION.md#从网页重建房间)。

## 近侧墙

靠镜头一侧的墙（背面朝向镜头或几乎侧对镜头的墙）不会挡住视线，而是变成半透明（不透明度 0.08），墙上的门窗、插座、窗帘、挂画随之变淡。高于 1.6 米的家具（衣柜、书架、白板）背靠近侧墙、或位于房间靠镜头的一半时也会变淡；转动视角时有 10 厘米的缓冲，不会在中线附近反复闪烁。

变淡的东西不投影，点选和手势会穿过它选中后面的家具；正在摆放的家具始终显示为实心。完整工具模式下，“环境”面板的“近侧墙”提供三种模式：

| 模式 | 效果 |
| --- | --- |
| 实心 | 所有墙正常显示 |
| 半透明（默认） | 如上所述 |
| 隐藏 | 上述会变淡的东西全部不可见，光照和点选仍按半透明的规则处理 |

碰撞和支撑检查不受显示模式影响。

## 光照

左侧“环境”面板提供五个时段和一盏中央顶灯：

| 时段 | 效果 |
| --- | --- |
| 普通光照 `balanced` | 中性的展示照明：半球光加两盏平行光 |
| 早晨 | 低角度、偏暖的阳光，窗边天光较弱，顶灯微亮 |
| 中午（默认） | 高角度、中性的阳光，窗边天光最强，顶灯微亮 |
| 下午 | 太阳方位改变、高度降低、颜色偏暖，窗边天光减弱，顶灯微亮 |
| 夜间 | 关闭日光，中央顶灯为主照明，可以关灯 |

- **日光方向**参考房间里最大的窗户所在墙面，没有窗户信息时使用房间坐标轴。窗边天光从主要窗户向室内逐渐衰减。
- **中央顶灯**位于房间包围盒中央、天花板下方，垂直照向地面，按距离平方衰减。完整工具模式下照射角度可在 60°–170° 之间调节（默认 160°，指完整光锥角）。白天顶灯保持夜间亮度的 7% 作为补光。顶灯的开关和角度按房间保存在当前浏览器中，切换时段时保留。
- **环境光与阴影**：Three.js 的 RoomEnvironment 在初始化时生成一次环境反射，补充 PBR 材质的环境受光；阴影使用 2048² PCFSoft，并按房间范围自动收紧阴影相机。白天有太阳和窗边天光两张阴影图，夜间开灯时只有顶灯一张。
- **静态环境遮蔽（AO）**：默认 GTAO，补充家具接触处和缝隙的暗部。拖动、转视角、开合动画时暂停，停止约 350 毫秒后按半分辨率（长边最多 960 像素）补算一次，静止后不再请求帧。玻璃、透明虚影、编辑指示和碰撞网格不参与遮蔽。
- **画面调色（实验，完整工具模式）**：曝光（−2～+2 EV）、白平衡冷暖（−1～+1）、对比度（0.6～1.4）、饱和度（0～1.6）。拖动滑条只重做一次全屏合成，不重算模型、阴影或 AO。
- **导入物品随光照变化（实验，完整工具模式）**：为照片重建的家具启用 PBR 受光材质（保留已有贴图，补齐缺失法线并接收阴影）。默认使用照片原有的明暗。

半透明的近侧墙和高家具在时段光照下仍然挡光，只是不在淡化的表面上显示阴影；窗玻璃让直射光通过。图形功能或插件不可用时，相应效果自动停用，编辑器照常工作。

### 网址参数

| 参数 | 作用 |
| --- | --- |
| `time=balanced\|morning\|noon\|afternoon\|night` | 打开时的时段，默认 `noon` |
| `indoor=off` | 打开时关闭顶灯（不改变房间已保存的设置） |
| `lighting=off` | 完整的原始光照，用于对比；`lighting=initial` 为早期的增强参数 |
| `ao=off` / `ao=n8ao` | 关闭环境遮蔽 / 改用 N8AO |
| `env=off`、`shadows=original` | 关闭环境反射、使用原始阴影参数，用于分项对比 |
| `materials=pbr` | 打开时预选“导入物品随光照变化” |
| `lightingLab=1` | 开启 `roomLightingLab` 调试接口：固定状态保存与恢复、材质检查、镜头回放和 GPU 计时 |

控制台里的 `roomEditor.snapshot().lighting` 可查看当前环境、阴影参数和 AO 状态。

## 开合部件

切到顶部“体验”，点门、柜门、抽屉、窗即可打开，再点一次关上（约 0.45 秒的动画）。鼠标移到能开合的部件上时变成手形，并提示是什么、点一下会怎样（如“抽屉 · 点击关上”）。

- 柜体在重建中按扫描尺寸做过不均匀缩放，所以门按世界坐标中的合页线整体转动，不会变形；推拉部件沿自身的轴移动。
- 放在部件上的东西会一起动：升降桌升起时桌上的显示器、键盘、杯子一起上升，钢琴顶盖掀起时谱子跟着转。重建结果只记录了“放在桌子上”，所以编辑器打开房间时按形状判断：同组中底部正好压在该部件上（向下 6 厘米内接触）的物品跟随它，叠放的东西跟随下面那件。
- 回到“布置”时全部关上，摆放和碰撞检查都按关闭状态计算；开合状态不保存。变淡的近侧墙上的门、被窗帘挡住的窗需要换个视角再点。

示例房间中，room3 有 8 个可开合部件（衣柜和柜子的 6 扇门、房门、一扇推拉窗），office 有 4 个（房门、两扇平开窗、升降桌）。

## 漫游

在“体验”中点“走进房间”，以第一人称在房间里走动（眼睛离地 1.6 米）：

| 操作 | 作用 |
| --- | --- |
| 中键拖动画面（触屏直接拖动） | 转头 |
| `W` `A` `S` `D` / 方向键，按住 `Shift` | 走动，快走 |
| `Q` / `E` | 升高 / 降低视线（离地 0.5–2.2 米） |
| 点门、柜门、抽屉、窗 | 开合，与“体验”相同 |
| `Esc` / “退出漫游” | 回到进入漫游前的模式 |

漫游时碰到墙和家具会停下。

## 添加与导入家具

`scripts/serve.py` 只转发这几类地址给物体重建服务，写请求只接受本页面发出的：`/viewforge/assets/`（物品目录、尺寸、模型）、`/viewforge/objects/`（上传、抠图、重建、进度）、`/viewforge/dimensions/<结果>`（保存实测尺寸）。服务的部署见 [物体重建](../docs/OBJECT_RECONSTRUCTION.md)。

- **添加家具**（家具库里的第一张卡片）：分四步用照片新建家具——
  1. 命名，拖入照片（1–40 张 JPEG / PNG；1 张也能重建，绕物品从不同角度多拍几张效果更好；浏览器能解码的 HEIC 会先转成 JPEG）；
  2. 抠图预览（BiRefNet）：绿色是识别出的物品，点一张可以不用它，至少保留 1 张；
  3. 重建（DA3 深度 + MV-SAM3D，一般 3–8 分钟，GPU 繁忙时排队）；
  4. 查看结果，填一条实测边长，放进房间。

  重建在服务器上进行，关闭对话框或刷新页面都不影响；卡片上显示进度，刷新后会继续跟踪。服务重启后任务进度无法恢复，但结果照样会出现在“从已生成的模型添加”里。照片、抠图、结果和尺寸都保存在物体重建服务的数据目录中。
- **补拍**：重建结果旁有一支橙色箭头指向建议补拍的方向（由 COVER 计算），“看推荐角度”把预览相机移到推荐视角。点“补拍”上传新照片：原来的照片全部保留并复用抠图，只给新照片抠图，然后在原结果基础上重建，生成一个新结果，原结果不变。导入时选中已有的结果也可以补拍；没有补拍建议的旧结果同样能补拍。
- **从已生成的模型添加**：列出已有的重建结果。在物体重建服务中保存过标定的自动填好尺寸，没有标定的填一条实测边长。显示用完整模型，碰撞和支撑用轻量预览模型（同一坐标，三角面约 1/40）。导入后放在离房间中心最近的空地上，再用鼠标或手势摆放；导入时需要重建碰撞索引，room3 约 10 秒。
- **尺寸预览**：显示红色 X（宽）、绿色 Y（深）、蓝色 Z（高）三个箭头，点击轴标签选择实测方向，旋转视角时标签跟随。
- **删除**：导入家具的卡片右上角有删除按钮，只删除当前房间中的这一份实例，服务器上的重建结果保留，可以重新导入。房间原有的家具不提供删除。

## 家具库与手势

- **家具库**：默认收起，用左侧栏按钮、关闭按钮或 `Esc` 开合，不改变画布大小和取景。按 `/` 展开并搜索家具。
- **手势**：点击左侧“手势”打开面板，再点 **开启手势与摄像头** 启动本机摄像头；收起面板时识别继续运行（侧栏有圆点提示），在面板内点 **关闭手势与摄像头** 才停止。左手比 1 / 2 / 3 / 4 切换移动、抬高、场景缩放、旋转；左手捏合环绕视角，右手捏住家具或家具库卡片操作。松手后家具停成预览，右手竖拇指约 0.5 秒、放置按钮或 `Enter` 确认，确认时同样经过碰撞和落下检查；拇指向下取消预览。双手捏合拉开 / 靠近缩放场景。摄像头画面上显示镜像骨架和左右手的识别状态，场景中显示双手指尖、连线和中点；手跟丢时操作冻结，回来后松手重新抓取。导出布局只接受鼠标和键盘。完整说明见 [手势接入](../gesture/docs/roomcanvas-integration.md)。

## 测试

单元测试和模型检查不需要安装依赖（Node 24、Python 3），CI 全部运行：

```bash
node --test 'web/editor/tests/*.mjs'
node --test web/scripts/test_room_reconstruction.mjs
python3 -m unittest discover -s web/scripts
node web/scripts/check_room.mjs --scene-dir samples/room3      # 约 30 秒，适用于任何房间
for c in collision wall_mount seat_support gravity; do node web/scripts/check_$c.mjs --scene-dir samples/office; done
```

光照相关的浏览器检查需要 Playwright，先在另一个终端运行 `serve.py`。Playwright 装在仓库外的临时目录，不改动仓库依赖：

```bash
npm install --prefix /tmp/roomcanvas-lighting-tools playwright
npx --prefix /tmp/roomcanvas-lighting-tools playwright install chromium
PW=/tmp/roomcanvas-lighting-tools/node_modules/playwright
for c in lighting import_lighting lighting_stability time_lighting; do
  node web/scripts/check_$c.mjs --output /tmp/roomcanvas-$c --playwright $PW
done
```

默认使用 Playwright 自带的 Chromium，也可以用 `--browser <浏览器路径>` 指定。各脚本覆盖的内容：

| 脚本 | 检查内容 |
| --- | --- |
| `check_lighting.mjs` | 固定镜头和布局下的整体、近景截图，逐帧 CPU / GPU 计时；支持 `--rooms`、`--variants`、`--frames` |
| `check_import_lighting.mjs` | 用合成模型走完整的导入和摆放流程，检查受光材质与原显示的切换 |
| `check_lighting_stability.mjs` | 悬停和移出画布时不重绘、半透明墙前后一致、移动后正确更新 |
| `check_time_lighting.mjs` | 五个时段、顶灯定位与衰减、角度和开关、按房间保存、调色只做一次合成、窄屏和键盘操作 |

输出包含示例房间的截图，请放在仓库外，不要提交。

## 使用说明

- **布局保存范围**：保存和导出的布局包含房间原有的家具；导入的家具在刷新后从“从已生成的模型添加”重新加入。每次打开房间先显示原始布置，从房间菜单“继续上次布置”恢复。
- **重模型的碰撞检查**：落点的完整碰撞检查在后台线程中进行，页面保持流畅；钢琴、琴凳这类紧挨着的高面数模型约需 1–2 秒，期间预览显示黄色“检查中”，此时点确认会在检查完成后自动放下。
- **原有交叠**：重建结果中原本就相互穿插的物品（如家具与墙面贴合处）不计为碰撞，其余照常检查。插进墙里的白板、书架打开时显示“待调整”，挪开即可。
- **独立手势页**：编辑器最矮 640 像素，独立手势页的窗口太小时，家具库会落在 iframe 可见区域之外；推荐使用编辑器内置的手势。
