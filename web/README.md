# 网页编辑器

RoomCanvas 的网页部分：房间选择页（`index.html`）列出房间，点进布置编辑器（`editor/`）。

编辑器在浏览器里按真实尺寸布置重建出的房间：单击物品查看尺寸和位置，拖动或用摇杆、转盘、升降拉杆调整，确认后放置；物品可以收进物品库再放回；逐三角面检测碰撞和支撑面，可撤销重做，布局保存在当前浏览器里，也能导入导出 JSON。纯前端，使用 Three.js r180（`vendor/`，与 npm `three@0.180.0` 逐字节一致），没有构建步骤。

## 启动

本机需要 Git、Python 3 和 SSH 客户端，网页无需安装 Python 包或执行前端构建。服务器先按 [物体重建部署](../docs/OBJECT_RECONSTRUCTION.md#部署) 安装并启动 API；要在网页上重建房间，再按 [从网页重建房间](../docs/ROOM_RECONSTRUCTION.md#从网页重建房间) 启动房间重建服务。

**本机**，任意目录先执行 `ssh '<SSH 主机>'` 验证登录，登录后用 `exit` 返回本机。主机可用 `~/.ssh/config` 中的别名或 `user@host`。然后从准备存放源码的目录开始（已有仓库则直接进入 `RoomCanvas/`，省略克隆）：

```bash
git clone https://github.com/innovationasuna/RoomCanvas.git
cd RoomCanvas
python3 web/scripts/serve.py --ssh '<SSH 主机>'
```

打开 <http://127.0.0.1:7880/web/>，选择房间。`serve.py` 用一条 SSH 连接建立两个隧道：本机 `127.0.0.1:7865` 到 SSH 主机一侧的物体重建服务 `127.0.0.1:7862`，本机 `127.0.0.1:7866` 到房间重建服务 `127.0.0.1:7866`。按 `Ctrl-C` 停止网页时隧道一起关闭。房间重建服务没有启动时，原有房间和添加物品照常使用，只是“重建房间”提示服务未连接。后续从本机 `RoomCanvas/` 运行同一启动命令即可；更新代码时先停止网页，再执行 `git pull --ff-only`。

**本机**，在 `RoomCanvas/` 根目录，服务不是监听 SSH 主机的回环地址时，用以下命令替代启动命令：

```bash
python3 web/scripts/serve.py --ssh '<SSH 主机>' --remote '<监听地址>:7862'
```

`<监听地址>` 要填从 SSH 主机能连接的服务地址；服务器的 `--host` 必须绑定可由这一侧访问的接口。容器中监听 `0.0.0.0` 时，用宿主机映射地址或可达的容器 IP 作 `--remote`，不填 `0.0.0.0`。地址对应关系见 [启动与检查](../docs/OBJECT_RECONSTRUCTION.md#启动与检查)。房间重建服务的地址不同时加 `--room-remote '<地址>:<端口>'`。本机隧道端口需更换时，加 `--viewforge http://127.0.0.1:<端口>` 或 `--room-backend http://127.0.0.1:<端口>`。

**本机**，在 `RoomCanvas/` 根目录，只用编辑器时执行：

```bash
python3 web/scripts/serve.py
```

无需服务器也能打开示例房间、调整布局（示例房间的模型不在 Git 里，`serve.py` 启动时在后台下载缺少的，见 [示例房间的模型](#示例房间的模型)），之前用 `--ssh` 启动时缓存到 `runs/room-cache/` 的重建房间和回放也能打开；[添加与导入物品](#添加与导入物品) 需要物体服务在线，[重建房间](#重建房间) 需要房间重建服务在线。如果已有外部隧道，同样省略 `--ssh`，并确保隧道在 `127.0.0.1:7865` / `7866`，或用 `--viewforge` / `--room-backend` 指向它。

## 界面

编辑器是深灰框架、黄铜色选中反馈和明亮的三维画布。左侧窄栏上方是物品库、撤销、重做，下方是手势、环境和设置；这些面板一次只展开一个，开合不改变画布大小和镜头。

- **选择和调整分开**：单击物品只显示详情（宽、深、高，相对初始位置的 X / Z / 高度偏移和旋转角度），不改变位置。拖动已选物品，或拖动详情面板里的移动摇杆、旋转转盘、升降拉杆，进入调整预览；拉杆离中心越远速度越快。确认或取消后结束，确认后可撤销重做。壁挂物用摇杆沿墙移动，可以换墙。
- **镜头**：“整体”和聚焦物品使用透视视图，远处物体与网格自然缩小；“俯视”使用正交视图，方便对照尺寸。中键拖动旋转，右键拖动平移，滚轮缩放；左键只选择和调整物品，拖动空白处不转镜头。右下角“整体” / “俯视”切换视角。
- **物品库**：按“房间中 / 已收纳”筛选，可搜索，显示实物缩略图和尺寸。第一张卡片是“添加物品”，下方“从已生成的模型添加”导入已有的重建结果。
- **布置 / 体验**：顶部切换。“体验”里可以点击开合部件，或“走进房间”漫游。还有待确认的调整时，会先提示确认或取消。
- **房间菜单**：点击房间名，可继续上次布置、导入 / 导出布局、收起全部物品或恢复原始布置。每次打开先显示原始布置，不自动覆盖或恢复上次的存档；批量操作也能撤销。
- **设置**：简洁 / 完整工具、操作提示开关、重新查看上手引导，保存在当前浏览器。简洁模式选中物品后收起物品库；完整模式在宽屏同时显示物品库与详情，并在“环境”里提供室内灯角度、近侧墙、调色等更多选项。
- **选中反馈**：物品整体显示绿色高亮，取消选择恢复原材质；不再显示脚底的矩形色块。进入摆放预览后，继续用绿、红等颜色表示能否放置。
- **地面网格**：保留浅色背景，以房间主墙方向为固定坐标铺在真实地面下方，红、绿两条参考轴标示方向；主格 1 米、细格 25 厘米。线宽按屏幕像素绘制，细格在远处逐渐淡出，拉远时过渡到 10 米参考线，避免密集线条变成底纹。只作比例参照，不参与选择、碰撞和支撑；在“环境”中开关，漫游时隐藏。
- **上手引导**：随选择、调整提示下一步，可收起；保存状态会说明是否已存到当前浏览器。

界面过渡在 220 毫秒以内，只作用于界面，系统开启“减少动态效果”时停用。Manrope 字体随 `assets/fonts/` 离线提供（SIL Open Font License，同目录 `manrope-OFL.txt`），中文用系统字体。

## 房间文件

一个房间就是一个目录，里面两个文件：

- `Room.glb`：重建出的模型；
- `room_objects.json`：物品清单，用 `scripts/room_objects.py` 从重建结果的 `room_layout.json` 生成。

清单记录每件东西是房间结构、门窗、固定设施（插座、灯、窗帘、暖气片等，留在原处），还是可移动的物品；哪些东西一起移动（桌子连同桌上的东西、书架连同书）、挂在哪面墙上、哪些表面能放东西。房间重建时用 TRELLIS 重新生成的小物件（`room_layout.json` 中标有 `rebuilt`）单独成组，可以单独移动；放在家具上时随家具一起移动。物品名默认按类别自动生成（“柜子 1”）；在 `groups` 里给某组加 `"name": "钢琴"` 即可使用自定义名字，重新生成清单时会保留。

能开合的部件（柜门、房门、窗扇、升降桌）记在清单的 `joints` 里。`room_objects.py` 读取重建结果中每件物品的 `sim/<物品>.urdf`（默认在 `room_preview` 旁边的 `../room/Objects`，其他位置用 `--joints <目录>` 指定），只保留在 `Room.glb` 中能对应上的部件：部件是单独的节点，原点正好在关节上，自身不带旋转和缩放。对应不上的会打印原因并跳过。

编辑器打开房间时还会自动：从椅子网格中找出座面；把墙角的短墙连到两侧长墙上，使它们一起变淡；把没有记录墙面的窗帘归到它前方的墙。

### 房间选择页

房间选择页列出 `rooms.json` 里的房间（`id`、名字、目录、一句介绍），以及房间重建服务已完成的房间（服务在线时由 `serve.py` 合并进列表，不改写 `rooms.json`）。示例房间如果是某次重建的副本，在它的条目里用 `scan` 写上那次任务的编号，首页就只显示示例这一张。卡片上的物品数和模型大小直接从房间文件读取，缩略图是房间目录中的 `thumbnail.jpg`，由 `scripts/thumbnail.py` 从编辑器整体视角截图生成（需要 Playwright 和 Pillow）。手动添加房间只需在 `rooms.json` 加一行并生成缩略图。重建出来的房间也可以用它生成，缩略图放到服务器上该房间的发布目录，命令见 [使用与结果](../docs/ROOM_RECONSTRUCTION.md#使用与结果)。

打开方式：列表里的房间是 `editor/?room=<id>`；任意房间目录用 `editor/?scene=<相对 editor/ 的路径>`，例如 `editor/?scene=../../samples/room3`。要把编辑器发布到仓库外某个房间目录旁边，运行 `python3 web/scripts/publish.py --scene-dir <房间目录>`。

房间选择页与编辑器共用 `theme.css` 中的配色（`--rc-*` 变量）和 Manrope 字体；选择页布局在 `home.css` / `home.mjs`，编辑器布局在 `editor/form-workspace.css`。

### 示例房间的模型

示例房间的 `Room.glb`（三个共约 195 MB）不在 Git 里，是本仓库 [`sample-rooms` release](https://github.com/innovationasuna/RoomCanvas/releases/tag/sample-rooms) 的附件；`room_objects.json` 和 `thumbnail.jpg` 仍在仓库里。`samples/models.json` 逐个列出模型：放在哪（`path`）、release 的 `tag`、附件名 `asset`、字节数 `bytes` 和 `sha256`。**本机**，在 `RoomCanvas/` 根目录，只需 Python 标准库：

```bash
python3 scripts/fetch_samples.py            # 下载缺少或大小不对的模型
python3 scripts/fetch_samples.py office     # 只取指定房间（samples/ 下的目录名）
python3 scripts/fetch_samples.py --check    # 只报告缺什么，不下载；有缺失时退出码为 1
python3 scripts/fetch_samples.py --verify   # 已有的模型也核对 sha256
```

仓库是私有的，不能匿名下载：脚本先用已登录的 `gh`（`gh auth login`），没有时用环境变量 `GH_TOKEN` 或 `GITHUB_TOKEN` 中能读本仓库的令牌；两样都没有时列出缺少的文件和下载地址，在浏览器里登录 GitHub 下载后按所列路径存放。下载先写到同目录的 `Room.glb.part`，大小和 sha256 都对上才替换 `Room.glb`。

`serve.py` 启动时在后台下载缺少的模型（加 `--no-download` 只提示），下载不了不影响首页和其他房间，缺模型的房间在编辑器里提示“找不到房间模型”。本机已有但与清单不同的模型只提示、不覆盖；要换回清单里的版本，运行 `python3 scripts/fetch_samples.py <房间>`。

新增示例房间或更换模型：把模型上传为 release 附件，再在 `samples/models.json` 增加或修改对应的一条。

```bash
cp samples/<房间>/Room.glb /tmp/<房间>-Room.glb    # 附件名就是上传的文件名
gh release upload sample-rooms /tmp/<房间>-Room.glb -R innovationasuna/RoomCanvas
wc -c < samples/<房间>/Room.glb && shasum -a 256 samples/<房间>/Room.glb    # 填入 bytes 和 sha256
```

更换模型时建议换一个附件名而不是覆盖原附件，旧提交才能继续取到当时的模型。

## 重建房间

房间选择页的 **重建房间**（也可直接打开 `web/#reconstruct`）上传一个房间的完整扫描包（扫描 App 导出的 tar 或 ZIP，最大 2 GB），提交后显示实际的流水线阶段，失败可以重试；关闭页面不影响服务器上的任务，完成的房间自动加入列表。`serve.py` 只把 `/room-reconstruction/` 下的健康检查、任务、目录和已发布文件转给房间重建服务，写请求只接受本页面发出的，大文件分块转发。扫描格式、服务启动和接口见 [从网页重建房间](../docs/ROOM_RECONSTRUCTION.md#从网页重建房间)。

首页房间卡片也会显示排队和正在重建的房间，点击卡片进入实时查看；任务完成后自动切换为“进入布置”。封面右上角“…”菜单中的“删除房间”会在确认后将房间移入回收站（包括对应任务入口），刷新和重启后仍保留删除状态。页面右下角的“回收站”显示已删除房间的数量，点击后可查看并逐个恢复；入口悬停、聚焦及打开时与房间卡片一样高亮。恢复后房间和对应重建任务会重新显示。扫描和模型文件保留，运行中的任务不会被取消。此功能需要更新并重启 `serve.py`；删除记录保存在本机 `.roomcanvas/deleted-rooms.json`，不提交到仓库。

重建任务可以 **实时查看** 或 **查看过程**（`replay.html?job=<任务号>`）：左栏按阶段列出重建记录，右边三维视图从扫描点云、物品框一路变成最终房间，底部时间轴可拖动回看。说明文字、数据来源和接口见 [查看重建过程](../docs/ROOM_RECONSTRUCTION.md#查看重建过程)。

## 近侧墙

靠镜头一侧的墙（背面朝向镜头或几乎侧对镜头的墙）不会挡住视线：默认整面隐藏，也可以改成半透明（不透明度 0.08）。墙上的门窗、插座、窗帘、挂画随墙一起处理。高于 1.6 米的家具（衣柜、书架、白板）背靠近侧墙、或位于房间靠镜头的一半时也一样；放在这些家具或墙上搁板上的东西（书柜里的书、搁板上的包）按摆放检查认定的支撑关系跟着一起处理，不会悬在半空。转动视角时有 10 厘米的缓冲，不会在中线附近反复闪烁。

隐藏或变淡的东西不投影，点选和手势会穿过它选中后面的物品；正在摆放的物品始终显示为实心。完整工具模式下，“环境”面板的“近侧墙”提供三种模式：

| 模式 | 效果 |
| --- | --- |
| 实心 | 所有墙正常显示 |
| 半透明 | 上述东西变淡 |
| 隐藏（默认） | 上述东西全部不可见，光照和点选仍按半透明的规则处理 |

碰撞和支撑检查不受显示模式影响。

## 光照

左侧“环境”面板提供五个时段、一个“物理光照”选项和室内灯开关。室内灯来自房间里的顶灯（灯具位置见下）；房间里没有顶灯时，改用一盏中央顶灯：

| 时段 | 效果 |
| --- | --- |
| 普通光照 `balanced` | 中性的展示照明：半球光加两盏平行光 |
| 早晨 | 低角度、偏暖的阳光，窗边天光较弱，顶灯微亮 |
| 中午（默认） | 高角度、中性的阳光，窗边天光最强，顶灯微亮 |
| 下午 | 太阳方位改变、高度降低、颜色偏暖，窗边天光减弱，顶灯微亮 |
| 夜间 | 关闭日光，室内灯为主照明，可以关灯 |
| 物理光照 `physical`（实验） | 与 Android 漫游同款的物理光照（见下） |

- **日光方向**参考房间里最大的窗户所在墙面，没有窗户信息时使用房间坐标轴。窗边天光从主要窗户向室内逐渐衰减。
- **室内灯（房间里的顶灯）**：物品清单里装在天花板上的灯（类别 `light`、`light_fixture`、`luminaire`，`mount` 为 `ceiling`；台灯、壁灯不算）。每盏灯取其网格在地面上的最小外接矩形作为发光面（有自发光部件时只取发光部件，如灯片；转过角度的房间里灯条也保持真实长宽和方向），在发光面下 2 cm 放垂直向下的聚光灯：沿长边每 3.5 m 一盏、每盏灯具 1–3 盏、等距排列，全屋最多 6 盏（超出时先减少灯具上的盏数，减不下去再只保留发光面最大的灯具，去掉的灯具亮度并入最近的一盏）。各时段的总亮度为中央顶灯原有亮度（同样按房间高度和时段比例）乘以 `max(1, 地面面积 / 20 m²)^0.75`，按每盏代表的发光面积分配；地面面积由各墙内侧面围出（不超过房间包围盒）。所以 20 m² 以内、只有一盏顶灯的房间亮度与原来相同，大房间在整个地面上分布照明。夜间份额最大的 3 盏投影（1024² 阴影，偏移随光锥角度调整），白天不投影。不再显示发光小球，看到的就是灯具本身；灯具自身的自发光只跟开关走：开灯时在所有时段（含普通光照、物理光照）保持模型原值，关灯时降为 0（作用在灯具材质的独立副本上）。参数集中在 `editor/room-luminaires.mjs` 的 `LUMINAIRE_LIGHTS`。
- **中央顶灯（没有顶灯的房间）**位于房间包围盒中央、天花板下方，垂直照向地面，按距离平方衰减，带一个发光小球标出位置。
- 室内灯的照射角度在完整工具模式下可在 60°–170° 之间调节（默认 160°，指完整光锥角），作用于每一盏。白天室内灯保持夜间亮度的 7% 作为补光。开关和角度按房间保存在当前浏览器中，切换时段时保留。面板上开关显示“室内灯 · N 盏”（N 为灯具数），没有顶灯时显示“中央顶灯”。控制台里 `roomEditor.snapshot().lighting.time` 的 `luminaires` 列出找到的灯具（中心、方向、长宽、面积），`lights` 列出每盏灯（位置、份额、强度、是否投影、来源 `luminaire` / `fallback`），`floorArea` 为地面面积。
- **环境光与阴影**：Three.js 的 RoomEnvironment 在初始化时生成一次环境反射，补充 PBR 材质的环境受光；阴影使用 2048² PCFSoft，并按房间范围自动收紧阴影相机。白天有太阳和窗边天光两张阴影图；夜间开灯时只有室内灯的阴影：中央顶灯一张，房间里的顶灯最多三张。
- **物理光照（实验）**：移植 Android 漫游的 `PhysicalRoomLighting`（同源于房间流水线 `lighting="physical"`），用于和现有时段对比，尚未作为默认。物理相机 f/0.7、1/125 s、ISO 100（EV100≈5.94，曝光≈0.0136）；太阳 2500 lux、6500 K，方向固定为仰角 40°、方位 35°（不随窗户变化）；房间里有顶灯时，灯光来自上面的室内灯位置，每盏灯具按发光面积 100 W/m² 或长度 30 W/m 中较大的一个（限制在 10–250 W；灯带按面积算只有实际功率的三分之一，大房间会偏暗）分给它的几盏聚光灯，4700 K，按实际光锥角度换算坎德拉（角度越大坎德拉越低，总光通量不变），最多 6 盏；所有灯具合计不足 60 W 时按比例放大到 60 W（不比原来生成的那盏灯暗，如 room3 的 4 个筒灯各 15 W）。没有顶灯时，每块天花板下 5 cm 一盏 60 W（LED 光效，约 382 cd）4700 K 点光。每扇窗户往室内 8 cm、略向下一盏 20 W（约 279 cd）6500 K 聚光（内外锥 45°/85°）。投影的局部灯始终最多 4 盏（加上太阳，材质贴图较多时也不超过 16 个纹理单元）：没有顶灯时同原来，生成的天花板灯和窗户灯合计最多 4 盏，先天花板后窗户，全部投影；有顶灯时，顶灯聚光灯最多 3 盏投影，窗户灯最多 2 盏（先大后小），剩下的投影名额给较大的窗户。`snapshot().lighting.time.physical.shadowCasters` 列出投影的灯。模型自带灯时改用自带灯、不加太阳。天花板和窗户按房间标签识别（吊顶格栅、灯具、窗帘、窗外景不算），没有标签时按节点名前缀；天花板的高度取它自身的网格，不含挂在它下面的窗帘、灯具（回放里的模型没有展开层级，地面和墙的高度同样只取自身网格）。曝光预先乘进灯光强度（Filament 的做法），画面整体曝光不变，所以窗外照片、摆放预览和地面网格亮度照旧。手机上的环境光是绝对强度 0.25，只占顶灯照度约 1%，这里沿用 RoomEnvironment 按同样强度换算，不引入 HDR。点光阴影 1024²（手机 512² 配 PCSS），深度偏移为主、法线偏移很小，避免墙面条纹和薄部件（如办公室线管）自遮挡。室内灯开关同时控制这些顶灯或天花板灯；照射角度作用于顶灯的聚光灯，不作用于生成的天花板点光。手机只在室内漫游，编辑器的总览还会从外面看到墙：墙朝外的面、贴墙物件（门、窗框、踢脚线、线管等）朝外的面、墙体厚度里的端面和门窗洞侧面、比顶灯高且朝上的面（墙顶、窗帘盒、柜顶）以及天花板以上的部分，改用均匀的柔和天光（`exteriorLight`），不受太阳直射和顶灯影响，避免墙外侧过曝发白、灯照不到的顶面全黑。墙朝室内的一面保持物理光照，室内漫游画面几乎不变（只有门窗洞侧面改为天光）。
- **静态环境遮蔽（AO）**：默认 GTAO，补充物品接触处和缝隙的暗部。拖动、转视角、开合动画时暂停，停止约 350 毫秒后按半分辨率（长边最多 960 像素）补算一次，静止后不再请求帧。玻璃、透明虚影、编辑指示和碰撞网格不参与遮蔽。
- **画面调色（实验，完整工具模式）**：曝光（−2～+2 EV）、白平衡冷暖（−1～+1）、对比度（0.6～1.4）、饱和度（0～1.6）。拖动滑条只重做一次全屏合成，不重算模型、阴影或 AO。
- **导入物品随光照变化（完整工具模式）**：默认开启，保留已有贴图、补齐缺失法线并接收阴影。旧版顶点色模型可关闭该项作对照；标记为 PBR 的 MV-SAM3D 烘焙结果始终保留原材质并直接受光，不受这个旧版切换项控制。

半透明的近侧墙和高家具在时段光照下仍然挡光，只是不在淡化的表面上显示阴影；窗玻璃让直射光通过。图形功能或插件不可用时，相应效果自动停用，编辑器照常工作。

### 网址参数

| 参数 | 作用 |
| --- | --- |
| `time=balanced\|morning\|noon\|afternoon\|night\|physical` | 打开时的时段，默认 `noon` |
| `indoor=off` | 打开时关闭室内灯（不改变房间已保存的设置） |
| `lighting=off` | 完整的原始光照，用于对比；`lighting=initial` 为早期的增强参数 |
| `ao=off` / `ao=n8ao` | 关闭环境遮蔽 / 改用 N8AO |
| `env=off`、`shadows=original` | 关闭环境反射、使用原始阴影参数，用于分项对比 |
| `materials=pbr` / `materials=original` | 默认开启导入受光；`original` 仅关闭旧版顶点色模型的受光，原生 PBR 结果仍然受光 |
| `lightingLab=1` | 开启 `roomLightingLab` 调试接口：固定状态保存与恢复、材质检查、镜头回放、编辑器阶段和 GPU 计时 |

控制台里的 `roomEditor.snapshot().lighting` 可查看当前环境、阴影参数和 AO 状态。

## 开合部件

切到顶部“体验”，点门、柜门、抽屉、窗即可打开，再点一次关上（约 0.45 秒的动画）。鼠标移到能开合的部件上时变成手形，并提示是什么、点一下会怎样（如“抽屉 · 点击关上”）。

- 柜体在重建中按扫描尺寸做过不均匀缩放，所以门按世界坐标中的合页线整体转动，不会变形；推拉部件沿自身的轴移动。
- 放在部件上的东西会一起动：升降桌升起时桌上的显示器、键盘、杯子一起上升，钢琴顶盖掀起时谱子跟着转。重建结果只记录了“放在桌子上”，所以编辑器打开房间时按形状判断：同组中底部正好压在该部件上（向下 6 厘米内接触）的物品跟随它，叠放的东西跟随下面那件。
- 回到“布置”时全部关上，摆放和碰撞检查都按关闭状态计算；开合状态不保存。变淡的近侧墙上的门、被窗帘挡住的窗需要换个视角再点。

示例房间中，room3 有 8 个可开合部件（衣柜和柜子的 6 扇门、房门、一扇推拉窗），office 有 4 个（房门、两扇平开窗、升降桌）。

## 添加与导入物品

`scripts/serve.py` 只转发这几类地址给物体重建服务，写请求只接受本页面发出的：`/viewforge/assets/`（物品目录、尺寸、模型）、`/viewforge/objects/`（上传、抠图、重建、进度）、`/viewforge/dimensions/<结果>`（保存实测尺寸）。服务的部署见 [物体重建](../docs/OBJECT_RECONSTRUCTION.md)。

- **添加物品**（物品库里的第一张卡片）：分四步用照片新建物品——
  1. 命名，拖入照片（1–40 张 JPEG / PNG / HEIC / HEIF；1 张也能重建，绕物品从不同角度多拍几张效果更好）。按文件内容识别格式，HEIC / HEIF 在浏览器本地自动转成 JPEG，误改成 `.png` / `.jpg` 后缀的 HEIC 也能识别；JPEG / PNG 不重新压缩。转换时显示进度，确认预览可读取后才允许上传；失败会显示具体文件名。解码器随网页提供，仅在需要时加载，不向第三方发送照片；来源及许可证见 [`vendor/heic-to/`](vendor/heic-to/README.md)；
  2. 抠图预览（BiRefNet）：绿色是识别出的物品，点一张可以不用它，至少保留 1 张；
  3. 重建（DA3 深度 + MV-SAM3D，一般 3–8 分钟，GPU 繁忙时排队）；
  4. 查看结果，填一条实测边长，放进房间。

  重建在服务器上进行，关闭对话框或刷新页面都不影响；卡片上显示进度，刷新后会继续跟踪。服务重启后任务进度无法恢复，但结果照样会出现在“从已生成的模型添加”里。照片、抠图、结果和尺寸都保存在物体重建服务的数据目录中。
- **补拍**：重建结果旁有一支橙色箭头指向建议补拍的方向（由 COVER 计算），“看推荐角度”把预览相机移到推荐视角。点“补拍”上传新照片：原来的照片全部保留并复用抠图，只给新照片抠图，然后在原结果基础上重建，生成一个新结果，原结果不变。导入时选中已有的结果也可以补拍；没有补拍建议的旧结果同样能补拍。
- **从已生成的模型添加**：列出已有的重建结果。在物体重建服务中保存过标定的自动填好尺寸，没有标定的填一条实测边长。显示用完整模型，碰撞和支撑优先使用同坐标的 `collision.glb`；旧资产依次回退到 `preview.glb` 和完整模型。导入后放在离房间中心最近的空地上，再用鼠标或手势摆放。增删物品只构建新实体的几何和 BVH，复用已有支撑采样与静态索引。
- **尺寸预览**：显示红色 X（宽）、绿色 Y（深）、蓝色 Z（高）三个箭头，点击轴标签选择实测方向，旋转视角时标签跟随。
- **删除**：导入物品的卡片右上角有删除按钮，只删除当前房间中的这一份实例，服务器上的重建结果保留，可以重新导入。房间原有的家具不提供删除。

## 物品库与手势

- **物品库**：默认收起，用左侧栏按钮、关闭按钮或 `Esc` 开合，不改变画布大小和取景。按 `/` 展开并搜索物品。
- **手势**：点击左侧“手势”打开面板，再点 **开启手势与摄像头** 启动本机摄像头；收起面板时识别继续运行（侧栏有圆点提示），在面板内点 **关闭手势与摄像头** 才停止。左手比 1 / 2 / 3 / 4 切换移动、抬高、场景缩放、旋转；左手捏合环绕视角，右手捏住物品或物品库卡片操作。松手后物品停成预览，右手竖拇指约 0.5 秒、放置按钮或 `Enter` 确认，确认时同样经过碰撞和落下检查；拇指向下取消预览。双手捏合拉开 / 靠近缩放场景。摄像头画面上显示镜像骨架和左右手的识别状态，场景中显示双手指尖、连线和中点；手跟丢时操作冻结，回来后松手重新抓取。导出布局只接受鼠标和键盘。完整说明见 [手势接入](../gesture/docs/roomcanvas-integration.md)。

## 测试

单元测试和模型检查不需要安装依赖（Node 24、Python 3），CI 全部运行。模型检查读示例房间的 `Room.glb`，先取回模型（见 [示例房间的模型](#示例房间的模型)；CI 按 `samples/models.json` 缓存）：

```bash
node --test 'web/editor/tests/*.mjs' 'web/scripts/test_*.mjs'
python3 -m unittest discover -s web/scripts
python3 scripts/fetch_samples.py
node web/scripts/check_room.mjs --scene-dir samples/room3
node web/scripts/check_room.mjs --scene-dir samples/room-3934  # 57 件可编辑物品
for c in collision wall_mount seat_support gravity; do node web/scripts/check_$c.mjs --scene-dir samples/office; done
```

光照相关的浏览器检查需要 Playwright，先在另一个终端运行 `serve.py`。Playwright 装在仓库外的临时目录，不改动仓库依赖：

```bash
npm install --prefix /tmp/roomcanvas-lighting-tools playwright
npx --prefix /tmp/roomcanvas-lighting-tools playwright install chromium
PW=/tmp/roomcanvas-lighting-tools/node_modules/playwright
for c in lighting import_lighting lighting_stability time_lighting; do
  node web/scripts/check_$c.mjs --output /tmp/roomcanvas-$c --playwright $PW
done
node web/scripts/check_ground_grid.mjs --playwright $PW
node web/scripts/check_object_photos.mjs --playwright $PW
```

默认使用 Playwright 自带的 Chromium，也可以用 `--browser <浏览器路径>` 指定。各脚本覆盖的内容：

| 脚本 | 检查内容 |
| --- | --- |
| `check_lighting.mjs` | 固定镜头和布局下的整体、近景截图，逐帧 CPU / GPU 计时；支持 `--rooms`、`--variants`、`--frames`；加 `--asset-edits` 可在光照采样后导入并删除示例阅读椅 |
| `check_import_lighting.mjs` | 用合成模型走完整的导入和摆放流程，检查受光材质与原显示的切换 |
| `check_lighting_stability.mjs` | 悬停和移出画布时不重绘、半透明墙前后一致、移动后正确更新 |
| `check_time_lighting.mjs` | 五个时段、室内灯定位（房间里的顶灯或中央顶灯）与衰减、角度和开关、按房间保存、调色只做一次合成、窄屏和键盘操作 |
| `check_ground_grid.mjs` | 108 组透视 / 俯视、微小旋转及渲染合成的像素对比：地板遮挡网格，房间外的网格仍可见 |
| `check_object_photos.mjs` | 合成 HEIC 原图与误改 PNG / JPEG 后缀、预览尺寸和颜色、损坏文件提示及实际上传编码；模拟接口，不启动重建任务 |
| `check_replay_resources.mjs` | 24 次 draft 替换的真实 WebGL 资源稳定性；成形中替换、回拖、1/2/8 倍速、灯光切换和迟到 load / warm / prefetch；支持 `--output <报告.json>` |

每个光照档位的 `report.json` 条目在 `editorStages` 下保留最近 128 个分段样本。每个样本记录操作、阶段、页面内起点和耗时（毫秒），以及可编辑物品数。初次加载分开记录模型读取与解析的合计耗时、支撑构建、碰撞几何提取、主线程碰撞构建、Worker 提交和缩略图。`collisionWorkerSubmit` 从主线程准备或复用 Worker 开始，到数据打包并提交结束。`rebuild` 是资产增删时支撑与碰撞子阶段的总耗时；`floorSearch` 记录导入后的落点搜索。用 `--asset-edits` 时，显示模型和碰撞预览均使用仓库内同一份椅子模型，哈希见报告的 `conditions.assetEditModelSha256`。旧版页面的 `editorStages` 为 `null`。

输出包含示例房间的截图，请放在仓库外，不要提交。

回放的点云与线框 shader 池由单个 `RoomView` 复用，纹理材质的裁切副本随模型释放。
替换 draft 时先取消异步上传、移除成形效果和墙面淡出引用，再等待已开始的 shader 编译完成后释放该模型；
已过期的 GLTF 加载结果不会重新加入场景。销毁整个视图应调用并等待 `view.dispose()`，同时清理观察器、动画帧、环境贴图及 shader 池。
`check_replay_resources.mjs` 的稳定段必须有至少 20 次替换，`renderer.info.memory` 和 program 数量不得随替换持续增长。

## 使用说明

- **布局保存范围**：保存和导出的布局包含房间原有的物品；导入的物品在刷新后从“从已生成的模型添加”重新加入。每次打开房间先显示原始布置，从房间菜单“继续上次布置”恢复。
- **重模型的碰撞检查**：落点的完整碰撞检查在后台线程中进行，页面保持流畅；钢琴、琴凳这类紧挨着的高面数模型约需 1–2 秒，期间预览显示黄色“检查中”，此时点确认会在检查完成后自动放下。
- **原有交叠**：原始扫描可以显示、重置和撤销恢复，每件物品都能在扫描位置原地确认，但不会永久豁免相交物品对。扫描时就相交的一对，只有确实相交的连通部分按穿入深度判断：不超过扫描时的深度加 5 mm 即可放置，朝任意方向移开、抬起后原地放下和不加深的旋转都允许；比扫描时穿得更深的移动会在越界处停下。深度按这一对连通部分各自的凸包面计算，拖动哪一件结论都相同；没有接触过的部分走普通碰撞检查。
- **独立手势页**：编辑器最矮 640 像素，独立手势页的窗口太小时，物品库会落在 iframe 可见区域之外；推荐使用编辑器内置的手势。

### 几何与场景模块边界

`scene-editor.js` 连接场景状态与交互流程。实体分组与世界矩阵不变量在 `scene-entities.mjs`，导入模型构建在 `import-entity.mjs`，仓库行在 `warehouse-row.mjs`。`scene-geometry.mjs` 管理放置、碰撞、漫游索引及 Worker 生命周期，`collision-client.mjs` 管理增量传输、代际与异步请求取消。

`entity-geometry.mjs` 提供稳定原始几何；`collision.mjs` 建立的三角形 BVH 同时供 `ray-queries.mjs` 的最近命中查询复用。漫游按实时世界矩阵查询开门、抽屉及承载姿态，地板仍参与落脚判断。隐藏、透明和裁切按使用场景的查询策略过滤。物体增删不重建旧实体的 BVH，过期 Worker 回包不能确认新布局。

`check_lighting.mjs --asset-edits --editor-queries` 会在增删物品后验收原生/BVH射线、开合部件、真实 Worker、承载及漫游流程。`lightingLab=1` 时也可执行 `await roomLightingLab.queryBenchmark()`，按同一批射线运行 5 轮原生 Three.js / BVH 对照，并临时打开全部关节后复核、再恢复状态；返回耗时、差异数和三角形访问计数。普通编辑器不加载该基准模块。
