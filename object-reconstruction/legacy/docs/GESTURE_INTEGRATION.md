# 手势移动与旋转

更新：2026-10-17。已接入右手选择、捏合移动和自由旋转，以及左手数字模式切换、右手两指环绕/三指平移观察。本模块已迁入 RoomCanvas 的 `object-reconstruction/`，手势源码和运行资源在仓库根目录的 `gesture/`，房间交互、承托和碰撞继续由 ViewForge 处理。只运行一个 Babylon.js 3D 场景，手势入口不启动原 Three.js 演示。

## 本机使用

1. 保持 ViewForge 现有网页服务和 SSH 隧道可用：`http://127.0.0.1:7865/`。
2. 在本机拉取后的 RoomCanvas 仓库根目录启动手势工程。要求 Node.js 22.12+ 和 npm；也可在 `object-reconstruction/` 内使用兼容脚本：

   ```bash
   sh scripts/gesture.sh install
   sh scripts/gesture.sh dev
   ```

3. 打开 `http://127.0.0.1:8800/viewforge.html`。页面默认嵌入当前服务器的房间布局页；服务路径或隧道端口变化时修改“房间布局地址”，再点击连接。
4. 在嵌入的布局页中确认房间尺寸、选择已标定重建物体并加入场景。可继续使用原来的鼠标和侧栏操作。
5. 点击“开启摄像头”并授权；用左手 1/2/3 或按钮选择移动、旋转、仅观察。先松手，再让蓝色指针指向物体并捏合。
6. 移动模式保持捏合拖动；旋转模式保持捏合左右移动，整幅画面宽度对应 π 弧度。确认松手后进行服务器校验，通过才正式应用；失败恢复操作前位置。

摄像头默认关闭，用户按钮开启；关闭释放视频流和 Worker。只在本机浏览器识别，不上传摄像头画面。当前识别入口使用 localhost/127.0.0.1 的本地地址，未接入远程识别模式。

本机不再依赖独立手势仓库。依赖安装在 RoomCanvas 的 `gesture/node_modules/`，不纳入 Git。使用 Mutagen 时需显式排除 `**/node_modules/` 和 `**/dist/`；它不会自动使用 `.gitignore`。后续更新拉取 RoomCanvas 即可；首次使用仍需安装依赖，并配置可用的 ViewForge 服务与 SSH 隧道。服务器物体重建所需权重、环境、照片和历史结果仍在原数据目录，不随源码克隆。

默认场景入口为 `http://127.0.0.1:7865/viewforge/layouts/viewer`。服务器按实际源码目录重定向到布局页，保留手势会话参数，不在手势代码中固定服务器磁盘路径。端口变化时修改页面的房间布局地址，或传入 `?layout=<编码后的布局 URL>`。此入口需要运行更新后的 ViewForge 后端。

数据流：本机浏览器摄像头 → 本机 Worker 识别 → 同一浏览器内通过 postMessage 控制嵌入的 Babylon 场景 → 操作结束请求服务器承托/碰撞校验 → 通过后应用，保存时写入服务器。手势高频输入和相机观察不逐帧发送到远程服务器。

原手势仓库的五个提交已完整导入本仓库，原哈希、作者及时间保留；ViewForge 未提交阶段按记录补齐，目录迁移单独提交。以下阶段验证记录保留当时状态。

## 行为边界

- 默认仍是“仅观察房间”，必须选择移动或旋转模式才操作物体。
- 指针使用右手拇指/食指中点，复用既有滤波和捏合阈值。识别模块已做水平镜像，布局端不重复翻转。
- 场景画布左上为 `(0,0)`、右下为 `(1,1)`，不包含布局侧栏。镜像摄像头全幅映射到画布，不从视频显示裁剪推导控制坐标。
- 移动保留抓取偏移，沿地面或物体表面拾取；默认保留自动承托。旋转连续变化，不吸附到 15°。
- 开始释放首帧冻结预览，确认释放只提交一次。校验期间锁住物体编辑，不排队重放手势。
- 追踪短缺冻结预览，持续缺失/歧义约 200ms 中断并恢复原位；接收端无帧超过 250ms 同样保护。重获、模式切换和鼠标操作后先松手再抓取。
- 已确认松手进入校验后，随后丢手不取消该提交；明确点击取消、Esc、关闭摄像头或重新连接场景可取消。取消后的旧异步结果不能重新应用。
- 鼠标物体操作和手势物体操作互斥；鼠标拖动观察时也阻止手势抓取。
- 轻量模型即可操作，全量替换保留父节点和候选姿态。碰撞继续使用服务器完整网格。
- 左手数字选择和右手观察已接入；手势菜单、双手缩放、高度控制、自然深度和历史撤销尚未接入；手势原独立演示仍保留这些既有功能。

## 实现入口与协议

| ViewForge 文件 | 作用 |
| --- | --- |
| `viewer/src/layout-manipulation.ts` | 鼠标/手势共用候选姿态事务、异步校验、恢复及过期结果保护 |
| `viewer/src/layout.ts` | Babylon 拾取、移动投影、旋转、承托提交、鼠标与手势适配 |
| `viewer/src/layout-gesture.ts` | 右手操作状态、松手重抓保护、输入消息校验 |
| `viewer/src/layout-gesture-bridge.ts` | opt-in iframe 通信、来源/会话/序号与新鲜度检查、状态反馈 |

手势工程对应 `viewforge.html`、`src/integration/main.ts`、`runtime.ts`、`protocol.ts`；runtime 直接复用 CameraSource、Tracker 和 GestureEngine，不加载 Scene/Controller。

协议标识为 `viewforge-gesture-v1`。iframe URL 明确传入 `gesture_origin` 和 `gesture_session`；仅接受指定本机父窗口，校验 origin、source、会话和递增序号。发送指定目标 origin，不使用 `*`。

输入包括 `hello`、`mode`（view/move/rotate）、`frame`（仅右手归一化 u/v、pinching/started/ended/releasing、中断及歧义）、`stop`（明确取消）。追踪中断以 interrupted frame 表达，与明确取消分开。反馈为 `state`，包含 busy、mode、selectedId、layoutReady、phase、message 和已处理序号。不传输原始关键点、视频帧或世界位置。观察帧增加 observation: orbit/pan；布局通过 capabilities: [observe-pinch-v1] 宣告支持，state.phase 增加 observing。

`sampleTime` 为发送窗口 `performance.timeOrigin + 推理帧.timestamp`，接收端用自己的 timeOrigin + now 比较；不能直接比较不同窗口的 performance.now。超过 250ms 的旧输入不应用。

## 左手选模式与右手观察

左手 1（食指）选择移动，2（食指＋中指）选择旋转，3（食指＋中指＋无名指）选择仅观察，其他手指收拢。保持约 400ms 确认，空闲可直接稳定换另一数字。持续保持相同数字不重复触发，物体/相机操作和校验期间忽略切换；忙碌或追踪失效后先回中性手型（如张掌）再识别。

右手观察两指（拇指＋食指）捏合环绕；三指（拇指＋食指＋中指）合拢平移。动作抓取开始时锁定，转换需完全松手后重新抓取；不依赖模型拾取，也可在确认房间尺寸之前观察已加载的房间。释放首帧冻结、确认后固定；丢手终止并保留最后视角，明确取消恢复抓取前视角。

相机控制位于 viewer/src/layout-observe.ts，平移按抓取时视平面、距离和画布宽高比映射，环绕保留俯仰限制。不会修改 Item 或保存布局，也不会调用 validate。操作开始/结束清除相机角度、半径和 panning 惯性。

本阶段：ViewForge 32 项测试、手势 70 项测试、类型检查/构建及手势资源校验通过。Chrome 合成左右手关键点验证数字切换、忙碌忽略不重放、两指/三指动作锁定、相机释放/丢手/取消、布局不变与无碰撞请求；原移动、自由旋转、全量替换、碰撞拒绝及鼠标链路保持通过。尚未进行本阶段真人识别与方向/增益手感验收。没有提交、推送或重启后端。

## 左手显示与水平环绕反向

本轮按用户要求反转水平环绕；垂直环绕、平移和物体旋转方向不变。左手新增绿色显示指针，右手继续蓝色。接入页右侧展示左手检测状态、数字及确认进度，并提示右手需松开、场景忙碌或需张掌恢复。

输入帧新增可选 helper: {u,v}，只用于显示，校验有限且在 [0,1] 内；左手不进入物体操作控制。右手中断但仍收到左手时，绿色标记保留；全局停止或无新帧时清除。

手势数字判断修正自然握法的收拢指识别，不要求指尖末端强弯。浏览器合成自然握法验证左手独立选模式、绿色指针、确认/恢复反馈与反向水平环绕；手势 74 项、ViewForge 34 项测试及类型/构建、手势资源校验通过。本轮没有真人摄像头验收、提交或推送。
