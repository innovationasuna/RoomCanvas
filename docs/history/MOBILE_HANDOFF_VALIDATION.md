## Android 模拟器（2026-11-23）

当时在 macOS 使用官方 Android Emulator 37.3.10、Android 14（API 34）ARM64 镜像，虚拟设备为 `RoomCanvas_API_34`。配置为 2 GB 内存、2 核、720 × 1280，启用 Mac 硬件虚拟化和 GPU。

测试使用 RoomCanvas 0.2.0 调试 APK 与办公室快照 `2b938758`，模型大小为 41,920,296 字节。AR Engine 提示出现时选择“仅用方向键”。

| 检查 | 当时的结果 |
| --- | --- |
| 安装与启动 | 安装成功，确认版本名 0.2.0、版本号 2、ARM64。 |
| Chrome 唤起 App | App 冷启动、App 已运行两种情况下均完成导入。 |
| 文件与渲染 | 本地 GLB 的 SHA-256 与清单一致。墙面、物品与贴图正常显示。 |
| 方向键和滑屏 | 移动时视点位置改变，拖动右半屏时朝向改变。 |
| 回到起点与结束漫游 | 复位后回到原视角，退出后房间仍保留。 |
| 离线重开 | 关闭 Wi-Fi 和移动数据、确认无网络路由，再强制停止并打开 App，仍可加载房间、进入漫游。测试后恢复网络。 |
| 运行日志 | 本次测试未发现崩溃或 ANR。 |

测试期间沿用 App 的渲染代码与模型贴图分辨率。截图与版本记录保存在当时验证机的仓库相对路径 `output/android/emulator-test/`。这些记录随机器保存。

## 复现环境与真机边界

- 当时使用 macOS 用户目录下的 `Library/Android/sdk` 与 `.android/avd/`。`ANDROID_HOME` 可指定其他 SDK 路径。
- 启动脚本读取 `output/android/RoomCanvas-Mobile-0.2.0-debug.apk`，用 `adb install -r` 保留已有房间。
- 新启动实例的日志位于用户目录下的 `Library/Logs/RoomCanvas/emulator.log`，关闭模拟器窗口即可结束。
- 在模拟器 Chrome 中用 `10.0.2.2` 访问宿主机，保留实际分享端口和 `/s/<分享标识>/`，真机则使用电脑的局域网地址。[通用模拟器步骤](../../android-app/README.md#在本机模拟器上调试)
- 当时没有连接 Android 真机。Android / iPhone 在实际 Wi-Fi 下的扫码连通、App 导入与离线重开、设备渲染性能、iPhone Safari 以及华为 AR Engine 真机定位仍待对应设备验收。[原计划与状态](MOBILE_HANDOFF_PLAN.md#11-android-模拟器验证2026-11-23)
