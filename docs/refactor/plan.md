## 1. 对建议的判断

总体采纳“先修可靠性与正确性、再按测量优化、最后清理”的方向。上传阻塞应提高优先级；碰撞坐标修复需要同时建立稳定的几何接口。以下内容调整后采用：

| 原建议 | 本计划的处理 |
| --- | --- |
| 准备批必须全部完成才能修问题 | 先确认基线和必要测试；确定性的 bug 修复可并行推进。新增 stop/restart、全量浏览器 CI 不作为全部修复的前置条件。 |
| GPU 锁、并发保存、编译返回码一起出一个 PR | 三者独立提交。GPU 锁涉及多入口、等待、父子进程和旧部署迁移，单独验证。 |
| 修坐标时一次抽出整个碰撞服务 | 同一 PR 只引入稳定局部几何及位姿接口并修坐标；完整服务迁移、Worker 与增量索引后续交付。 |
| 用“穿透深度不超过初始值”替换永久豁免 | 先确定行为规则和反例。现有算法没有通用穿透深度，凹网格、薄片和开放网格不能用包围盒重叠深度代替；分离后也不能继续使用初始豁免。 |
| 给 save() 加锁就解决全部状态竞态 | 随机临时文件解决文件名冲突；共享状态还需要协调更新、快照与持久化顺序。不能仅保护最后的 rename。 |
| 漫游直接使用现有碰撞树 | 先补关节变换、地面和查询过滤规则，再共用几何与索引。现有树没有射线接口，也不跟踪开门等局部动画。 |
| 两处缓存各改一行 | TRELLIS 需要参数全链传递；articulate 需要让候选、视图、判断、切割、检查和最终产物一起随输入失效。 |
| 新建 `?perf=1`，因为没有浏览器测量工具 | 扩展已有 `lightingLab=1`、`render-metrics.mjs` 和 `check_lighting.mjs`；它们已有加载耗时、帧间隔、CPU/GPU 分位数和资源统计。 |
| trace.jsonl 成为所有状态的唯一来源 | 改为“每类事实有一个权威写入者”。任务状态、阶段状态和回放事件职责不同；先明确契约，再逐步统一事件读取。 |
| 统一每个阶段返回的结果 | 已有 `StageResult`，包含状态、warnings、artifacts、error、details 和耗时；沿用并贯通到 API/UI。 |
| 一次转换旧任务后删除推断 | 新任务使用版本化事件；旧任务保留适配器及 inferred/unknown 标记。确认覆盖和可回滚后，再决定是否移除旧路径。 |
| 补 author 中途续跑 | 当前已保留工作房间和语法检查点；补工作摘要、多文件一致性和恢复验证，不重建已有机制。 |
| 清理待提交回放改动后再动资源释放 | 成形/运镜修复已在 #71 合并，#75 又增加倍速播放。释放修复直接以当前实现为基线，覆盖这些功能。 |

“9 次尝试、约 8 小时、author 8737 秒”等保留为待核实的历史运行描述，本轮没有读取服务器原始日志。它们混合人工修复、等待、版本变化和缓存复用，不能用作对照验收阈值。[当前 Room_3934 清单](../../samples/room-3934/room_objects.json)和本地缓存均有 **23 个 joints**，“最终房间 0 个可开合部件”与当前清单不符；如果原意是某次 pass 新增 0 个，需要原始报告区分。计划评审时没有设备验证这些关节的实际开合效果；后续重构验收已在 Chrome 打开全部 23 个关节并对照射线查询。

现有 publish 允许在部分质量警告下产出可用房间，这是当前明确策略。先展示执行结果、质量结果和增强结果的差异，不把 warning 或“新增关节数为 0”直接改成失败。

## 2. 执行边界与依赖

- 原工作区的 `perf/object-reconstruction-profile`、README 服务器验证记录和 `object-reconstruction/experiments/` 由原性能试验继续使用。
- 后续批次开工时核对当时工作区与官方远程 `main`。首批在同一独立 worktree 联调，各行为改动分开提交，便于审查与回退。
- 每个 PR 对应一个可独立验证、回退的行为变化。先为真实缺陷补回归用例，不为简单文件移动编写复述实现的测试。
- 服务器验证与部署流程见第 6 节。当前实施记录覆盖本地开发。
- 现有数据、照片、权重、运行目录不作为源码清理对象。新测试尽量使用合成数据，私人截图和性能原始报告放仓库外。

| 批次 | 内容 | 前置依赖 | 完成条件 |
| --- | --- | --- | --- |
| 0 | 基线、测试入口、观测补齐 | 无 | 明确当前版本、测试覆盖与可比较的测量方法 |
| 1 | 小范围可靠性修复、上传响应与 GPU 调度 | 0 的代码基线；无需等待完整性能测量 | 失败被正确传播，同卡互斥，状态写入和请求响应稳定 |
| 2 | 编辑器坐标、原始接触规则、资产发布 | 对应基线和回归用例 | 渲染/碰撞/支撑/标定一致 |
| 3 | 缓存、阶段结果、输入规范、恢复与事件 | 1 的失败与保存语义 | 正确复用、可解释失败、新旧任务均可读取 |
| 4 | 碰撞、漫游、数据与渲染性能 | 相应正确性契约及性能基线 | 有量化收益且正确性与质量不回退 |
| 5 | 职责拆分与低收益清理 | 对应行为已稳定 | 减少重复入口，保持公开接口与必要覆盖 |

批次是默认优先顺序，不是全仓库串行闸门。回放资源释放、DA3 数据优化和其他模块的独立小修，可以在各自依赖满足后并行；修改同一碰撞状态与文件的任务保持串行。

## 3. 逐项实施步骤

### 批次 0：建立可比较的基线

**0A — 记录当前状态并补齐轻量测试入口。**

1. 记录提交、分支、相关改动、浏览器/设备和模型摘要；核查本地实验是否已有可复用结果。确认新的 `samples/room-3934` 纳入针对性验证，原有 `room3`、`office` 继续保留。
2. 将 `web/scripts/test_home.mjs`、`test_room_reconstruction.mjs`、`test_room_trash.mjs` 纳入 Node CI；当前仅语法检查覆盖了它们，没有执行其中的测试。
3. 分开安排浏览器功能检查、性能对照、Android 构建/设备验证。Android 当前未进 CI 是已有文档约定，添加 JDK/SDK 任务单独处理；不把软件 GPU 上的绝对 FPS 作为通用 CI 门槛。

验收：命令能够执行全部轻量 Node 测试，新增场景有明确运行入口；测试报告注明环境性跳过和未执行部分。

**0B — 扩展已有观测，生成后续性能工作的基线。**

1. 复用 `web/editor/render-metrics.mjs`、`web/scripts/check_lighting.mjs`，补模型解析、支撑构建、碰撞构建、导入/删除、落点搜索、漫游查询的分段计时，以及 long task 和输入到画面的延迟。
2. 固定模型哈希、相机轨迹、viewport/DPR、光照和手势状态，分别记录冷加载与热加载。浏览器样本记录可见性、聚焦、硬件/软件 GPU；被后台节流的样本不用于判断流畅度。
3. 覆盖初次加载、移动重物、导入/删除、漫游转角、开门、静止和回放切模型。短场景至少重复 5 次，保存原始样本、p50/p95、最长主线程任务和资源数。
4. 物体重建优先衔接现有 `experiments/` 诊断；房间分开记录排队、CPU/GPU 执行、模型/API 等待和重试。昂贵全流程只在必要时验证，不为获取统计反复调用付费服务。

验收：每项待优化工作有目标指标、测量方法和噪声范围。先定比较口径，再改实现；不要求先完成新的诊断面板。

### 批次 1：先消除随机失败和请求阻塞

**1A — 并发状态保存，独立 PR。**

- 修改范围：`small_objects/run.py` 的 `Pass.save/reference`、`web/scripts/room_cache.py` 的 `save` 及对应测试。
- 复用 `dimensions.py::atomic_json` 的同目录唯一临时文件及原子替换方式；保持模块依赖轻量，不为复用此模式跨重建环境导入整个脚本模块。共享 `self.items` 由协调线程更新和保存，或使用同一锁覆盖更新、快照及提交；请求缓存还需定义并发响应的覆盖顺序，避免较旧响应覆盖新版缓存。
- 验收：以 barrier 控制并发写入交错，JSON 始终完整、无临时文件冲突、已完成字段不丢失；重复执行、异常中断后仍可读；临时文件清理完整。

**1B — 编译失败传播，独立 PR。**

- 修改范围：`room_ops/api.py::compile_room`、`agent/tools/compile/tool.py`，核对 publish 的调用契约。
- 检查 assemble、bake 的返回码与本次产物；只有各项成功才更新成功 stamp。保留日志和失败候选，旧 GLB 存在不能充当新编译成功的证据。
- 验收：assemble 成功但 bake 非零时明确失败；不写成功缓存；修正环境后重试确实执行；原本成功的构建不增加重复烘焙。

**1C — 大数组极值，独立小修。**

- 将 `placement.mjs` 等处理不受限几何数组的 `Math.min/max(...array)` 改为遍历求极值；检查空输入和非有限值沿用的错误语义。
- 验收：20 万三角面的合成输入不再因参数数量崩溃，原样例和边界输入结论不变。

**1D — 上传暂存与状态锁，房间与物体分别提交。**

- 房间：在全局任务锁外解压、校验；用上传 ID 保留占位或独立互斥，避免移锁后同 ID 同时解压、清理对方目录。短锁只提交任务记录和入队。
- 物体：将文件复制、完整解码、导入和清理移入线程池中的磁盘工作单元；限制并发。临时目录校验通过后发布，全部照片失败不占名称，部分失败明确返回到 UI。
- 保留现有上传大小、路径与扫描包限制；断开、失败、重复上传和队列提交均有清晰结果。
- 验收：人为暂停解压/复制时，健康与任务查询能在它完成前返回；同 ID 只入队一次；损坏 JPEG 不进入抠图步骤，同名修正重试可用；失败无半成品目录残留。

**1E — GPU 锁协议，独立 PR 与服务器验证。**

首批核对发现，房间入口 `server/run_room.py` 的主任务锁位于 `runtime/locks/gpu-<UUID>.lock`，自动追加的 articulate 子进程在释放该锁后启动。物体抠图、重建和独立 COVER 使用 `VIEWFORGE_GPU_LOCK` 或 `VIEWFORGE_ROOT/cache/gpu.lock`，由重建触发的 COVER 带 `--lock-held`。迁移用例需分别启动这些真实入口。先在临时目录内用假 GPU 验证一张物理卡对应同一把锁，并验证父任务退出时的所有权，再用独立服务器 worktree 验证。

- 使用物理 GPU UUID 标识资源，统一房间、物体抠图/重建/COVER 等入口的锁位置、选择、等待、取消和失败反馈；处理 `CUDA_VISIBLE_DEVICES` 索引/UUID 映射和显式旧锁配置。
- 先保持现有作业级持锁范围，不同时改成常驻模型或阶段级调度。拿锁后复查资源；父进程持锁调用子进程时明确所有权，避免子进程重复锁死。
- 使用稳定锁文件，不通过删除/重建文件“释放锁”。迁移前确认旧任务结束或完成兼容安排，避免新旧进程各持不同锁。
- 验收：多进程假任务验证同卡互斥、异卡可并行、等待可取消、异常退出释放、无卡预览可用；随后独立 worktree 验证两条真实入口使用同一资源协议。正式切换不得打断运行任务。

**1F — 只读缓存的离线回退，独立 PR。**

- 对明确可缓存的 GET，在连接失败及选定的临时网关错误（如 502/503/504）时使用旧副本，并提供来源/陈旧状态；恢复连接后更新。健康检查仍反映真实在线状态。
- 不对写入、重试或 400/403/404 等业务错误伪造成功。任务版本变化时同时清理旧文件和此前的 404 缺失记录。
- 验收：网关在线、后端离线时缓存房间可读；无缓存正确报错；业务错误不被旧结果掩盖；后端恢复和任务重试后读到新版本。

### 批次 2：统一几何与资产的正确性

**2A — 稳定局部几何与位姿，优先于碰撞提速。**

- 定义不可变的对象基准几何、实体位姿及派生变换边界。不能从已经应用 layout 的世界坐标重新提取几何后，再应用同一 layout。
- 让渲染、碰撞、支撑通过明确接口获得同一位姿；这一步只做必要的接口抽取，不捆绑整文件重写或完整增量索引。
- 验收：移动/旋转/升降后，导入和删除其他物品不改变原物品的碰撞、支撑位置；包含父子承载、收纳、撤销/重做、恢复原布局与导入布局；主线程与 Worker 对同一候选结论一致。

**2B — 原始相交的行为规则与实现，接在 2A 后。**

- 默认行为目标：初始扫描可展示与恢复；允许脱离原始相交；禁止新增或扩大穿透；完全分离后使用正常碰撞规则。撤销可恢复历史布局，不因此给之后的新移动永久豁免。
- 先用贴合家具、开放薄墙、凹网格、旋转和承载组合建立反例，选择可支持的接触区域/脱离方向/穿透度量。不能以 AABB 重叠深度替代精确几何规则。
- 如果现有算法不能可靠实现某个边界，先明确受限规则与交互提示，再单独审查该行为；不静默退回整对 mesh 永久忽略。
- 验收：原有轻微相交可以搬离；两物体完全重合被拒绝；分开再穿过被拒绝；旋转和承载不引入新穿透；恢复/撤销的规则确定且可重复。

**2C — 资产就绪与尺寸标定，后端独立 PR。**

- 明确 `mesh_ready`、`asset_ready`、`recommendation_ready` 的不同条件。模型、材质能力和稳定坐标变换完整发布后，才允许正式 catalog/标定；推荐计算可后续完成，但不能再改变已发布的坐标契约。
- 更新 `assets.py`、`dimensions.py`、`run.py`、COVER 产物与前端错误显示。为已有无新 manifest 的历史结果提供明确兼容规则，不能一刀切从物品库消失。
- 验收：仅存在 GLB 的运行中任务不能标定；ready 后标定在推荐生成前后不失效；发布中断没有半套资产；失败结果与历史成功结果可区分；补拍产生新结果而不修改旧实例。

### 批次 3：完善缓存、失败解释与恢复

**3A — TRELLIS 与可动部件缓存，分别提交。**

- TRELLIS：贯通 flow、统一 options、Local/Modal service 和 launcher 的 force/skip、seed、decimation、纹理尺寸；缓存绑定输入内容、模型/代码版本和参数；失败后不得用上次 GLB 冒充本次成功。
- articulate：用 pass 级输入 fingerprint 管理候选 items、box/views、照片、plan、cut、check 和 final 的依赖；同样检查 small_objects 的“只比较 plan”缓存。size/mtime 只作快速探针，内容标识才决定复用。
- 验收：同输入可复用；输入内容或参数变化、force 正确触发失效；即使尺寸/mtime 未变也能识别内容变化；中途失败不会发布旧模型配新布局；旧缓存可明确升级或失效。

**3B — 输入规范、结构化结果与 UI，按层拆 PR。**

- 复用现有 `extract_scan` 的校验，和 ingest 共用目录规范化及帧/深度配对规则；先用原始格式 fixture 验证再增加内容检查，避免上传端与流水线各自接受不同格式。
- 沿用 `StageResult`，补稳定错误类别、是否可重试和产物有效性；已知输入缺陷在入队前报告。瞬时错误有限重试，输入和确定性程序错误不无限重跑。
- API/UI 分别呈现“执行结束”“产物可用”“质量结果”“可选增强结果”。关节报告区分已有、候选、新增、跳过和失败数；只展示与用户判断有关的信息。
- 验收：缺失输入尽早拒绝，错误可定位到阶段和必要文件；完成但有警告可见；硬失败不显示成功；0 新增关节有原因。保持现有一次验收/一次修复策略，是否改成质量硬门槛另行决定。

**3C — 新版事件与历史适配。**

- 为新事件定义 schema、job/run/attempt、stage、event ID/顺序、时间、outcome 和 artifact digest；明确多进程写入协调、终态持久化和重复事件处理。所有正式编译入口经统一包装写产物事件；检测到未记录的外部改写时标记未知，不能编造精确时间。
- 任务存储负责排队/执行状态，阶段存储负责复用，事件流负责进度/回放投影。新回放优先事件；旧任务的日志/mtime 推断放进独立适配器，保留来源和 inferred/unknown 标记。
- 验收：重试 attempt 不串线，重复幂等，乱序可确定排序，半行写入/进程中断可恢复；复制文件改 mtime 不改变新版事件时间；旧任务仍能打开。确认历史覆盖前不删除兼容路径，不原地批量重写原始任务。

**3D — author 恢复摘要与一致性检查。**

- 在现有保留工作目录和语法检查点之上，保存输入/配置 fingerprint、源码及必要资源摘要、已完成项、未完成项和最后有效产物。恢复前检查对应关系；新会话显式读取这些信息。
- 先实现文件级可靠恢复，不要求重构所有 provider 的 session resume。多文件变更采用一致检查点，语法通过不能代表 Blender 构建已验证。
- 验收：中断后不丢已保存物体、不无故重跑有效阶段；输入改变使旧检查点失效；损坏检查点有明确回退；force 仍按既定备份规则重做。可靠性用故障注入和固定数据集验证，不以“少于历史 9 次尝试”替代。

### 批次 5：职责拆分与低收益清理

1. 在稳定接口上拆分 `scene-editor.js`：场景状态、摆放控制、碰撞查询、资产导入、渲染/界面。每次迁移一项职责，避免同时重命名和改变行为。

## 6. 合并、服务器验证与部署

合并、服务器验证和部署遵守根目录 AGENTS.md。

1. 在本地完成源码、测试与提交，使用官方 GitHub 地址推送与 PR。不得把镜像保存为 remote 或配置地址重写。
2. 需要服务器环境时，以本地明确提交创建正式目录之外的独立 worktree，使用独立端口和输出。正式目录保持 main；复用环境、权重与缓存前核对兼容性，需要改依赖则用独立环境。
3. 验证 worktree 的 README 按项目要求记录目标/状态、分支/基线、改动、命令与环境、日志/结果、改动去向、保留理由或清理条件；不记录凭证。
4. 通过验证并合入 main 后，检查正式目录分支、HEAD、受版本控制文件改动与运行任务，仅在满足条件时快进更新。存在独有内容先保全，不 reset 或强制切分支。
5. 获取代码、更新目录、重启进程分开判断。健康信息若增加版本字段，应报告进程启动时的提交/构建版本，不能随目录 git HEAD 改变而冒充新进程。
6. `stop/restart` 作为独立运维改进：先明确进程身份、排空/拒绝新任务、忙碌时行为、子进程归属和重启恢复；物体任务目前在内存中，不能直接按端口 kill。它不阻塞前面本地修复。
7. 验证结束停止不再需要的进程，记录是否保留 worktree；保全有效改动与必要结果后再清理。正式部署记录提交和关键验收，回退使用前一已验证版本及兼容的数据读取路径，不覆盖任务产物。
