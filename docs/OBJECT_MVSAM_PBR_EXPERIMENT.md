## 启用的实际能力

此前 [`run_inference_weighted.py`](../object-reconstruction/run_inference_weighted.py) 硬编码 `with_texture_baking=False`、`use_vertex_color=True`。本次增加 [`mvsam_pbr.py`](../object-reconstruction/scripts/mvsam_pbr.py) 适配器，由 [`run_reconstruction.py`](../object-reconstruction/scripts/run_reconstruction.py) 按配置启用原生 `to_glb()` 烘焙分支，不修改重建模型源码。

```yaml
mesh_export:
  mode: baked_pbr
  texture_size: 2048
  roughness: 1.0
  metallic: 0.0
  texture_padding: nearest
```

将完整配置通过 `run.py --backend mvsam3d --config /path/to/baked.yaml` 传入，原有 `mesh_export.mode: vertex_color` 保持兼容。烘焙结果由运行目录的 `materials.json` 告知网页保留 PBR；不生成会丢失贴图的旧简化预览。Gaussian、COVER 和后续补拍能力仍属于原 MV-SAM3D 流程。

这里的 PBR 是 **Gaussian 外观渲染 → UV 颜色贴图＋固定材质参数**。原生实现从生成的 Gaussian 渲染 100 个 1024 分辨率观察，进行 2500 步纹理优化；不是对原照片做光照与材质分离，也没有预测逐区域粗糙度、金属度或法线贴图。适配器显式设定非金属 `metallic=0`、`roughness=1`，记录 `predicted_material_maps=false`。

## 运行隔离及依赖

独立服务器目录：`/workspace/geyinuo/roomcanvas-mvsam-pbr-20261028-6ob62u7m/`。源码清单及哈希在 `code/source-manifest.json`；权重和 MV-SAM3D 环境只作复用，输入使用副本，结果写入新运行目录。串行使用空闲 GPU 1，父进程依次持有项目全局 GPU 锁及该卡场景锁，子运行再持有独立内部锁，不停止其他作业。

该二进制在本次 MV 环境 `torch 2.5.1+cu121` 下通过兼容检查，不代表其他机器或 Torch 版本也兼容；部署时需要单独验证依赖，不应把实验目录的绝对路径硬编码进项目。

## 对照方法

玩偶与沙发都用一张既有照片及确认蒙版，seed 42、DA3 504、MV 50／25 步。TRELLIS 采用先前同一照片生成的单图结果，2048 贴图、约 50,000 面目标。两模型的生成算法和面数预算不同，灰模另行比较，不将材质变化当作几何收益。

每次 MV-SAM3D 生成只采样一次；在同一份 mesh 解码结果上分别导出 `vertex-color.glb` 和带 UV／纹理的 `result.glb`，关闭网格简化及补洞，避免改变形状。UV 接缝可能增加顶点数，需用三角形空间坐标检查几何，而非只比较顶点数量。

渲染四列：

1. 同次 MV 顶点色，原 Basic 显示。
2. 同一顶点色模型，统一受光，粗糙度 1、金属度 0，与 MV 烘焙参数一致。
3. 同次 MV 原生烘焙 PBR，2048 颜色贴图、固定材质参数。
4. TRELLIS.2 原生 PBR，保留其基础色及金属度／粗糙度贴图。

第 2、3 列的材质参数相同，但颜色来源有区别：顶点色来自 mesh decoder，烘焙颜色来自 Gaussian decoder 的渲染。因此颜色改善不能仅归因于“从顶点色换成 UV 存储”，也不能归因于恢复了粗糙度或金属度。

相机、环境及灯光一致，高度统一为 1 并保留宽深比例；额外提供统一灰材质、统一粗糙度的颜色对照及移动光源视图。项目测试与截图使用临时服务，私人照片、GLB 和运行产物均留在仓库外。

## UV 空隙填补与恢复导出

第二次尝试 `baked_a02` 完成了 UV、观察图和纹理优化，但在原生 OpenCV `inpaint` 填补 UV 空隙时持续单核 CPU 运算。非暂停调用栈采样定位到 `postprocessing_utils.py:578`；只停止了这个自建实验工作进程，保留快照和失败记录，没有停止其他作业。

新增 `texture_padding: nearest`，只对 UV 栅格化标记为未覆盖的 texel 做最近邻扩边，已覆盖 texel 数值逐点不变；可设为 `native` 保留原生 Telea。该变化影响空隙及纹理滤波边缘，不改变生成的几何、已覆盖颜色或材质参数。它不是新的材质生成模型。

玩偶从 `baked_a02` 的 Gaussian、原始 mesh 和校验通过的 UV 缓存恢复到新目录 `baked_a03`，恢复导出 63.0 秒成功；这个数字不包括之前完成的模型采样和 UV，不能与 TRELLIS 的端到端耗时直接比较。由于此前未保存 SAM3D 姿态参数，该恢复运行只提供模型、Gaussian 和尺寸预览，不虚构 COVER 推荐。沙发则用相同最终配置重新完整运行 DA3、MV 和烘焙。

沙发 MV 全程的整卡显存采样最大值为 20,024 MiB，玩偶恢复导出为 5,254 MiB；后者不含加载和采样，不能与完整推理峰值比较。每两秒采样会漏掉短时峰值；两模型耗时包含不同的加载、生成及导出流程，且 MV 保留远多于 TRELLIS 的三角面，不能当成固定面数下的模型速度基准。

两组都用三角形空间坐标归一排序后校验，精度为 `1e-6`，烘焙与同次顶点色版本的几何哈希相同、包围盒相同。UV 接缝使顶点数增加，但三角面数不变，证实本轮变化来自颜色、材质和可能的接缝法线差异，没有重新生成几何。

MV 的两份 PBR 输出均只有颜色贴图和固定 `roughness=1`、`metallic=0`，不含 roughness／metallic／normal 贴图。原 GLB 未显式导出法线，网页由网格计算；TRELLIS 结果有法线、UV、颜色及金属度／粗糙度贴图。PBR 类型或贴图存在不代表材料属性与实物一致。

### 定性观察

- **先修受光显示已有明显收益。** 第二列仅把同一份 MV 顶点色模型改为受光材质，玩偶和沙发的明暗、体积及坐垫边界已经明显。此步骤无需重新生成模型或等待 UV 烘焙。
- **烘焙改善了部分颜色表达，但不是整体材质恢复。** 第三列玩偶的红心较深，白色身体带暖色及明暗残留；沙发抱枕的金色和局部图案比顶点色更明显。统一粗糙度／金属度后仍有颜色差异，符合两种 decoder 颜色来源不同，不能全归因于高光参数。未验证拍摄光照已被去除。
- **与 TRELLIS 各有取舍。** MV 玩偶表面较平顺、五官和红心完整，TRELLIS 表面起伏更明显，不能把更多凹凸直接当作真实毛绒细节。MV 沙发保留分块坐垫，TRELLIS 坐面较连续；TRELLIS 抱枕颜色及图案更鲜明，但两模型都存在未观察表面的猜测。
- **烘焙没有改变几何优劣，也没有稳定的整体胜者。** 本轮只是两物体、各一张照片、seed 42 的定性对照，未测扫描几何真值、反射参数真值或多 seed 稳定性。
- **成本需要单独权衡。** 原生颜色烘焙不增加几何精度，当前完整网格 UV 很重，GLB 也变大；若仅需受光，优先用已有顶点色受光入口。需要颜色贴图时再选择烘焙；需要更真实的材料响应时，应固定几何继续测试去光照与粗糙度／金属度估计。

## 后续改进：固定几何的分区材质增强

记录日期：2026-11-02。状态：**待验证，未实施**。当前方向保留 MV-SAM3D 的几何、多图、Gaussian 和补拍流程，在其颜色烘焙结果上研究逐区域材质属性，不以替换整套几何重建模型为前提。

### 与现有烘焙、场景受光的关系

三项能力分别处理不同问题：

- **MV 几何重建**决定形状、轮廓与结构。
- **当前颜色烘焙**发生在网格和 Gaussian 生成之后、最终 GLB 导出之前，将 Gaussian 外观渲染为虚拟视角，再优化到 UV 颜色贴图；不自动恢复粗糙度、金属度，也不自动去除拍摄或生成外观中的明暗。
- **场景实时受光**由前端材质、灯光、环境反射和阴影设置共同决定；不开烘焙的顶点色网格同样可以受光。分区材质进一步决定各位置如何响应这些光照。

当前烘焙输出使用统一 `roughness=1`、`metallic=0`。后续目标是在固定网格上增加属性贴图，让不同位置具有不同参数，继续封装为 GLB，不要求将每个材质区域拆成独立物体。

### 目标属性与预期收益

| 属性 | 预期收益 | 边界与观察重点 |
| --- | --- | --- |
| 粗糙度贴图 | 光滑与粗糙区域产生不同的高光宽度、反射清晰程度；区分布料、磨砂与光滑塑料等质感 | 不能简单把照片亮区设为低粗糙度；应检查移动光源后的响应 |
| 金属度贴图 | 区分裸露金属与非金属的反射方式，使脚架、螺丝等部位与布面呈现不同质感 | 金色不等于金属；金色布料仍应按非金属处理，整个物体均为非金属时统一 0 可以合理 |
| 法线贴图 | 用局部受光变化表达织纹、颗粒、细小压纹，在不增加同等几何面数的情况下增加表面细节 | 不改变真实轮廓、碰撞或几何投影，不能修复坐垫分块、缺失结构等几何问题 |

属性可通过贴图按表面位置表达，相关规范与示例见 [Khronos 材质说明](https://github.khronos.org/glTF-Tutorials/gltfTutorial/gltfTutorial_010_Materials.html)、[多贴图材质示例](https://github.khronos.org/glTF-Tutorials/gltfTutorial/gltfTutorial_014_AdvancedMaterial.html)。法线贴图对实际形状的限制及材质因子约定见 [Three.js MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)。

按现有样本推测，布艺沙发和毛绒玩偶可优先验证粗糙度、细微法线；含裸露金属、塑料、皮革等混合材料的物体再重点验证金属度分区。材料种类需核对实物或参考信息，不能只根据颜色猜定。上述收益尚未在本项目实测，也不意味着属性贴图越多，效果必然越真实。

### 候选方案与输出要求

1. 先在已有 MV 网格／UV 上手工指定少量已知材质区域，作为验证显示收益的对照；再考虑支持固定几何的材质估计或生成模型。候选能力沿用 [重建与材质调研](RECONSTRUCTION_MODEL_RESEARCH.md)，是否能保留几何和正确导出仍需逐项验证。
2. 输出保留网格、颜色贴图及尺寸标定契约，按实际生成情况增加粗糙度／金属度和法线贴图；通常可将粗糙度与金属度装入同一张 glTF 材质贴图。若重新展开 UV，以空间三角形、包围盒和显示变换核对几何一致性，不能仅比较顶点数。
3. 检查材质因子与贴图的组合。尤其不能给当前 `metallicFactor=0` 直接添加金属度贴图后就认为金属属性已生效：因子与贴图相乘时仍会得到 0。应验证最终渲染参数，保留不带贴图旧资产的兼容路径。
4. 记录输入、方法、模型版本、贴图分辨率、实际生成的通道、参数来源和耗时。区分人工指定、模型估计与固定值，不把“存在贴图”标记为“已恢复真实材质”。

更真实的反射还需要合适的场景灯光和环境反射；材质贴图本身不等于实时反射了房间内所有物体。颜色中的固定阴影应作为去光照问题另行验证，增加粗糙度／金属度／法线贴图不会自动消除它。

### 后续对照与验收

- **固定对照条件**：同一份 MV 几何、输入照片、UV 和颜色贴图，统一相机、曝光、灯光、环境与贴图预算，以现有烘焙＋固定参数为基线；分别增加粗糙度、法线，再对适用物体验证金属度，最后测试组合。若同时修改基础色／去光照，应另开一组，避免混淆收益来源。
- **观察随光变化的质感**：移动光源、切换观察方向，检查材质边界、高光宽度、细纹、UV 接缝与固定明暗残留；结合参考照片或实物，不能只用“更亮”“阴影更深”作为质量提升标准。
- **保留几何与产品流程**：核对形状、尺寸、朝向，以及 GLB 预览、场景导入、受光、摆放和旧结果读取；不把法线生成的视觉凹凸当成真实几何精度收益。
- **同时记录成本**：材质估计／烘焙耗时、GLB 大小、贴图展开后的资源负载，以及相同设备与场景下的 GPU 帧时间。额外贴图不必增加面数，但会增加纹理与采样成本，不能直接承诺性能不变。
